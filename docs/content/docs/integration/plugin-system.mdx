<Callout type="warn">
`github.com/xraph/grove/plugin` defines plugin interfaces and a registry, but nothing in Grove uses them yet: `grove.Open` has no plugin option, and no code calls the registry. Everything that extends Grove today (audit logging, metrics, tenant isolation, CRDT sync) does it as a hook added with `db.Hooks().AddHook`. See [Hooks](/docs/hooks/overview).
</Callout>

## The plugin Package

```go
import "github.com/xraph/grove/plugin"

type Plugin interface {
    Name() string
    Init(ctx context.Context, db any) error
}

// Optional extensions of Plugin.
type WithHooks interface {
    Plugin
    RegisterHooks(hookEngine any) error
}

type WithMigrations interface {
    Plugin
    MigrationGroup() any
}
```

`plugin.NewRegistry()` returns a `*Registry` with `Register`, `Get`, `Plugins` and `InitAll(ctx, db)`. If you want a plugin pattern in your own code, you can use the registry yourself and call `InitAll` after opening the database.

## Extending Grove with Hooks

A hook is any type that implements one or more of the hook interfaces (`hook.PreQueryHook`, `hook.PostQueryHook`, `hook.PreMutationHook`, `hook.PostMutationHook`, `hook.StreamRowHook`). Add it with a scope:

```go
db.Hooks().AddHook(myHook, hook.Scope{
    Tables:   []string{"orders"},
    Priority: 10,
})
```

With the Forge extension, pass hooks as options instead: `groveext.WithHook(h, scope)` or `groveext.WithHookFor(dbName, h, scope)`.

## Built-in Hooks

### Audit Logging (`grove/audit`)

A post-mutation hook that records every INSERT, UPDATE and DELETE through a `Writer`:

```go
import "github.com/xraph/grove/audit"

// Write entries through your own Writer (a Chronicle adapter, a table, a queue).
db.Hooks().AddHook(audit.NewHook(myWriter))

// Or log them.
db.Hooks().AddHook(audit.NewLogHook(logger))
```

`audit.Writer` is one method, `WriteEntry(ctx, *audit.AuditEntry) error`. Grove doesn't ship a Chronicle writer, so adapting it is up to you.

### Query Metrics (`grove/observability`)

A hook that times queries and mutations and reports them to a `Collector`:

```go
import "github.com/xraph/grove/observability"

collector := observability.NewInMemoryCollector()
db.Hooks().AddHook(observability.NewHook(collector))
```

`observability.Collector` is one method, `RecordQuery(table, operation string, duration time.Duration, err error)`. Implement it to forward to Prometheus, OpenTelemetry or anything else. Grove doesn't register any Prometheus metrics itself.

### CRDT Sync (`grove/crdt`)

`crdt.New(...)` returns a `*crdt.Plugin`. Despite the name it's added as a hook, not through the plugin registry. See [CRDT Getting Started](/docs/crdt/getting-started).

## KV Store

The KV module (`grove/kv`) shares the `grove/hook` package with the ORM, so a hook that only looks at `hook.QueryContext` can run on both. KV-specific behavior lives in KV middleware and plugins. See the [KV Middleware Overview](/docs/kv/middleware/overview).
